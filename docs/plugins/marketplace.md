# 插件市场与停靠工具

2026-10-05 本地开发版本。顶部「插件」打开插件市场。工具位置按用户截图接入现有底部浮动工具栏与右侧面板。

## 选择工具

市场包含三类内容：

- **内置基础工具**：输出规则、广播输入、项目任务、远程文件、录制回放。随主程序提供，可打开、停用和调整位置，无需下载。
- **官方扩展**：项目导航、Git 工作台、工作区笔记、屏幕摘录、命令看板、终端广播、命令片段、端口看板、任务面板。显示已安装／未安装，点击「安装」才复制到用户插件目录并启用。
- **自定义插件**：通过「导入插件目录」安装的 DLL 或声明式脚本插件，出现在已安装列表中。

搜索名称、功能或插件 ID；筛选全部、已安装、未安装、内置基础工具或官方扩展。停用保留配置，卸载删除插件目录及其保存的配置。官方目录和九个安装资源随主程序携带，可以离线安装；当前未接入社区远程目录或上传服务。

## 位置与启动

已安装插件卡片直接显示「打开位置」，选择底部或右侧后立即出现对应入口，无需重启。默认是「独立窗口」，因此安装后不会自动增加底部图标或右侧标签。也可从卡片点「设置」，或打开「位置与启动」页调整启动方式和快捷入口：

| 选项 | 行为 |
| --- | --- |
| 独立窗口 | 沿用工作区工具窗口，通过左侧导航选择模块 |
| 底部工具栏 | 在原有监控／SSH／日志／Deploy 工具栏中加入图标入口，点击后在右侧面板打开插件 |
| 右侧边栏 | 在原有进程／文件／日志／SSH／命令／AI 标签中加入插件标签，点击显示插件页面 |
| 手动打开 | 启动应用时保持关闭 |
| 启动时打开 | 每次启动都打开此工具 |
| 恢复上次打开 | 上次退出应用时工具仍打开，则重新打开；主动关闭面板后不再恢复 |
| 显示快捷入口 | 控制底部图标或右侧标签，隐藏后仍可从市场打开；独立窗口沿用左侧模块导航 |

显示范围、当前工作区和排序继续生效。位置变化移动原页面，笔记、输入和选择保持；不会重启或关闭终端。右侧插件页面的「↗」移到独立窗口，「×」返回之前的内置页面。右侧标签较多时自动换行，底部工具栏较宽时可横向滚动。

底部入口和右侧标签共用原有右侧内容区域，恢复上次打开时恢复其最后选中的插件。切换到进程、文件等内置页面或主动关闭右侧面板后，插件不再标记为正在打开；缓存页面保留。独立工具窗口单独记录其最后选中的工具。打开工具只打开页面，Git 提交、推送和 GitHub 写入仍由各自按钮触发。

## 项目导航设置

在插件设置页调整跟随当前终端、默认目录、隐藏目录、完整路径显示、最近访问数量（1–50）和紧凑布局。关闭跟随时，默认目录用于首次打开或没有浏览记录的工作区；空或不存在的默认目录使用用户目录。隐藏目录包括点开头目录和系统 Hidden 属性目录。

目录名称默认简洁展示，完整路径可悬停查看。修改设置立即保存，切换设置页或停用前的文本不会漏存。

## Git 工作台设置

设置包括跟随项目／活动终端、默认远端、默认 PR／Issue 基础分支、提交历史数量（1–200）、操作输出数量（1–100）、终端命令完成后刷新、差异自动换行和紧凑布局。

没有已选远端和已有上游时，使用默认远端作为偏好；默认基础分支用于打开新仓库时填写表单。历史数量在刷新时应用，输出数量和差异换行立即应用。窄侧栏中改动列表与差异上下排列，宽面板中左右排列。

Git 和 gh 沿用系统安装及现有认证。市场安装插件不会安装 Git／gh，也不会保存 token。

## 开发与打包

`dotnet build src/TerminalHub.App/TerminalHub.App.csproj` 会构建九个官方插件，并把 DLL、deps 描述和清单放到主程序输出的 `official-plugins` 目录。`dotnet publish` 也携带这些资源。Windows 便携 ZIP／安装包、Linux 打包脚本包含同一组插件资源，不收集用户配置。

第三方插件使用 `ExtensionSurface.WorkspaceTools` 注册工具页，即可获得宿主的位置和启动设置；使用 `ExtensionSurface.Settings` 注册自己的设置页。既有 API 1 插件继续可用，用户配置缺少新字段时默认使用独立窗口和手动启动。

## 验证结果

2026-10-05 位置纠正后：63 项相关回归全部通过，0 失败、0 跳过。包含 `PluginMarketplaceTests`、项目插件 UI、原有官方插件、插件二轮、工作台主题与会话布局回归。最后调整市场快捷入口选项后，8 项市场回归再次全部通过。

- 市场从真实附带资源安装插件，验证已安装／未安装筛选、搜索、停用和卸载；终端会话继续运行。
- 笔记页面在独立窗口、底部和右侧间反复移动，使用同一控件，笔记与会话保留。
- 设置文本即时保存，隐藏目录、最近访问限额、提交历史限额、默认基础分支和差异换行实际生效；停用后重新启用仍保留。
- 真实创建并关闭多次主窗口，验证手动、随启动打开和恢复上次状态，且恢复同一面板最后选中的工具。
- 底部入口位于原 `ActionDock` 胶囊工具栏中，右侧标签与页面位于原 `InspectorTabs` 面板中；打开插件不改变已显示侧栏时的终端宽高，原监控／SSH／日志按钮仍切换对应内置页面。
- 十个工具栏入口可在原胶囊内横向滚动；隐藏的插件标签仍可从市场打开，打开后有临时标签，关闭后恢复隐藏。
- Headless 实际绘制检查覆盖英文最小市场窗口、深色和 Paper 主题，确认原侧栏标签与新增插件标签均在可见范围内。临时截图检查后清除。

本轮验证抓到并修复了跨 TopLevel 迁移缓存页面的旧布局队列引用、恢复到此前访问页面，以及七个清单被发布到同一路径的问题。相关检查分别守住这些已复现的问题。

位置纠正还抓到右侧选择回调中重置原 ListBoxItem 容器导致重复挂载的问题，以及横向滚动把原进程／文件标签挤出可见区域的问题。现保留六个原容器，新增标签在受限宽度内换行；相关切换和绘制回归已覆盖。

Windows 自包含发布成功，便携包经检查包含主程序、描述正确位置的离线手册和七个插件各自的 DLL、deps 描述及清单（共 21 个安装资源文件）。位置纠正版输出到 `artifacts/plugin-market-placement/TerminalHub-windows-x64-preview.zip`，可执行文件为同目录 `app/TerminalHub.exe`；单独插件包位于 `artifacts/official-plugins`。此前预览包目录保留，避免覆盖正在运行的版本。

系统文件选择器／文件管理器人工操作、安装包实装、Linux 实机和 GitHub 线上登录／写入未执行；本轮绘制检查采用原生 Avalonia Headless，没有替代上述人工验收。未替换用户当前运行实例，未安装或上传发行包。

### 找不到新增入口时

仓库常用启动文件为 `app/TerminalHub.exe`。2026-10-05 跟进发现，该目录此前仍是旧产物；仅更新另一个预览目录不会更新它。现将常用启动产物与位置修正版同步更新。已有旧实例时，正常退出后再启动，否则单实例机制只会激活旧窗口。

打开顶部「插件」，在已安装 Git 工作台卡片上将「打开位置」从「独立窗口」改成「底部工具栏」或「右侧边栏」。项目导航如显示未安装，先点击「安装」，再选位置。8 项市场回归已通过，包含通过卡片下拉框切换后原底部图标和右侧标签立即出现；未修改用户保存的位置偏好或结束用户终端。
