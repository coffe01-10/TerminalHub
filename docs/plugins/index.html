01 / GET STARTED

安装与管理

新版主窗口顶部「插件」打开插件市场。市场展示五个内置基础工具、九个可选官方扩展及已导入的自定义插件，可以搜索并筛选已安装／未安装。找到需要的扩展，点击「安装」，再点击「打开」。九个安装资源随主程序附带，可以离线安装；目前没有社区远程目录或上传服务。

插件卡片的「设置」可调整位置、启动方式、快捷入口和工作区范围。项目导航与 Git 工作台还提供专用设置页。停用保留配置，卸载清除对应配置。

设置可选项
工具位置独立窗口（默认）、原有监控／SSH／日志／Deploy 底部工具栏入口、原有右侧面板标签
启动方式手动打开、启动时打开、恢复上次打开
快捷入口显示或隐藏底部图标或右侧标签；隐藏后仍可从市场打开

底部工具栏入口沿用监控／SSH／日志按钮的行为，在原有右侧面板打开插件。侧栏位置把插件标签加入进程／文件／日志／SSH／命令／AI 导航。工具迁移复用原页面，「↗」移到独立窗口，「×」返回之前的内置页面。退出应用保留上次打开状态，切换到内置页面或主动关闭侧栏则取消该插件的恢复；内置工具可停用或调整位置，无需安装。右侧标签较多时换行，底部工具栏可横向滚动。

源码开发或手动更新时，官方插件源码在仓库 plugins/ 下，运行以下脚本生成九个可导入目录和各自的 ZIP：

pwsh -File scripts/build-official-plugins.ps1
  1. 打开主窗口「插件」→「导入插件」。
  2. 选择 artifacts/official-plugins 中对应的插件目录。所选目录必须直接包含 plugin.json 和 DLL。ZIP 请先解压。
  3. 导入会立即启用。点击卡片「打开」，或从独立「工作区工具」窗口选择插件。
  4. 在「位置与启动」调整位置、启动、排序与工作区范围；旧版为「模块管理」。

更新时重新导入同 ID 的新构建目录。禁用会清理插件界面、计时器和订阅，不关闭终端进程。重新启用笔记恢复内容，摘录与看板从空状态开始。

移除插件会删除安装目录与该插件保存的配置，工作区笔记也会被删除。市场和插件目前以源码及本地包交付，尚未上传到发行页。旧版支持原有 API 1 插件；使用市场、项目导航和 Git 工作台请先更新主程序。

02 / OFFICIAL COLLECTION

九个官方插件

01

工作区笔记

official.workspace-notes

把交接信息、待办和排查结论留在当前工作区。切换工作区时切换笔记，关闭工具窗口保留编辑。

每秒保存待保存内容，点击「保存笔记」、切换工作区或停用时也会保存。写入本机用户配置，语言切换保留笔记原文。没有同步、上传或 Markdown 渲染。

02

屏幕摘录

official.screen-clips

先激活目标终端，再点「摘录当前屏幕」；也可通过命令面板执行。保存会话名、时间和纯文本，选择摘录后复制或导出 UTF-8 文本。

保留最近 20 份，停用或退出后清空。只抓当前屏幕缓冲整页，不包含历史浏览位置、选区或颜色。中文和 emoji 保留；物理行保留换行，去除行末空格和末尾空行。API 1 没有软换行元数据，不能重建逻辑行。

复制与导出由你主动点击，文本可能含项目私密信息，分享前请检查。

03

命令看板

official.command-watch

集中看各终端最近一次命令的状态、耗时和退出码。默认只看当前工作区，取消筛选可看全部会话，点击卡片回到相应终端。

只使用 Shell 集成标记。无标记显示「尚未收到命令标记」，缺少退出码显示未知。0 为完成，非 0 为失败。启用前不补录，不推断 AI 完成状态，不发送命令，不保存输出；某些 Shell 或 TUI 没有标记时无状态可显示。

更多官方插件

04

输入广播

official.terminal-broadcast

向当前工作区的运行中会话发送输入，发送前显示目标范围。支持只粘贴或发送回车；停用不结束终端。

05

命令片段

official.snippets

保存常用命令，点击粘贴进活动终端，检查后手动回车。片段保存在本机插件配置中。

06

项目导航

official.project-navigator

图形化浏览目录、面包屑与历史；收藏支持名称、分组、排序、搜索和 JSON 导入导出。浏览不会发送终端输入，点击「终端切到此处」或「在此新建终端」才操作指定会话。未知 Shell 状态可只粘贴目录命令。SSH 会话不会误打开同名本地目录。

收藏在本机共享，浏览位置和项目选择按工作区隔离；关闭工具窗口保留页面，停用后收藏仍保存。

设置页可选跟随终端、默认目录、显示隐藏目录、显示完整路径、最近访问数量（默认 12，1–50）和紧凑布局。文本设置立即保存。

07

Git 工作台与 GitHub

official.git-workbench

查看改动与差异，逐文件／全部暂存和取消暂存，提交、推送、获取、拉取、分支创建与切换、提交历史。远端和目标分支在「分支」页选择；失败保留原始输出。提交成功而推送失败时，可以单独重试推送。冲突文件可打开处理。

GitHub 页提供仓库主页、当前分支 PR、PR／Issue 列表和详情、检查状态、创建 PR 草稿、从 Issue 创建分支。需要系统 Git 和 gh；「GitHub 登录」打开一次性终端。PR 草稿请先推送当前分支；没有 gh 登录时本地 Git 继续可用。

「操作输出」记录命令、目录和退出码；取消只结束插件启动的进程。设置页可调整跟随、默认远端与基础分支、历史数量（默认 20，1–200）、输出数量（默认 30，1–100）、命令完成自动刷新、差异换行和紧凑布局。窄侧栏中改动与差异上下排列。

08

端口看板

official.port-guard

查看本机正在监听的 TCP 端口和 UDP 绑定。TCP 只留 LISTENING，UDP 只留对端 *:* 的绑定；IPv6 按方括号取端口。Windows 读 netstat 再用 tasklist 补进程名（按 OEM 代码页解码，中文表头按列位置解析）；Linux 依次尝试 ss 和 lsof，ss -o 省略队列列也能识别。可按端口、进程名或 PID 过滤，也可输入端口号查看占用。

结束进程前弹确认框，只有点「结束」才算确认，标题栏 X、取消、Esc 都视为取消。只接受快照里的整数 PID，拒绝 0、4、当前进程和手填值；结束的是整个进程而不只是这一端口，文案会说明 PID 可能被复用。诊断只在新终端展示命令输出。

09

任务面板

official.task-runner

读取项目目录的 package.json scripts、Makefile 目标、justfile 配方和 .vscode/tasks.json。「跟随项目／活动终端」默认开启，依次取项目导航所选和活动终端目录，切换工作区重新解析；关掉后「选择目录」把目录按工作区固定。目录、粘贴方式和跟随开关保存在本机配置。

勾选「粘贴到活动会话」时只写入命令、不按回车；取消勾选则新建一次性会话执行（cmd /d /s /c 或 sh -c，命令不包外层引号）。package.json 生成 npm run、Makefile 生成 make、justfile 生成 just，不执行脚本正文。没有这四个文件或没有可运行任务时，页面说明原因。

03 / BUILD YOUR FIRST PLUGIN

开发第一个插件

English plugin development tutorial →

完整开发教程：从零写一个命令草稿工具 →
包含完整工程、清单、全部源码、逐段讲解，以及配置、事件、主题、多语言、打包和调试步骤。

开发需要 .NET 8 SDK，安装插件的用户只需要宿主。可以从仓库的 examples/plugins/Minimal 开始，或从 v0.4.0 Release ↗ 下载 API 1 SDK，用下面的独立项目引用。

1. 创建类库

<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net8.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
  </PropertyGroup>
  <ItemGroup>
    <PackageReference Include="Avalonia" Version="11.3.2" />
    <Reference Include="TerminalHub.Extensibility">
      <HintPath>sdk/TerminalHub.Extensibility.dll</HintPath>
    </Reference>
    <Reference Include="TerminalHub.Core">
      <HintPath>sdk/TerminalHub.Core.dll</HintPath>
    </Reference>
    <None Update="plugin.json" CopyToOutputDirectory="PreserveNewest" />
  </ItemGroup>
</Project>

2. 添加 plugin.json

以下项目名假设为 MyPlugin；入口 DLL 必须与实际构建的文件名一致。

{
  "id": "my.hello", "name": "我的工具", "version": "1.0.0",
  "entry": "MyPlugin.dll", "entryType": "MyPlugin.Plugin", "hostApi": 1
}

3. 注册视图和命令

using Avalonia.Controls;
using TerminalHub.Extensibility;

namespace MyPlugin;
public sealed class Plugin : IWorkbenchPlugin
{
    public void Initialize(IPluginContext context)
    {
        context.RegisterView(new("hello", "我的工具"),
            () => new TextBlock { Text = "Hello Terminal Hub" });
        context.RegisterCommand(new("paste", "粘贴示例文本", () =>
        {
            if (context.Host.ActiveSessionId is { } id)
                context.Host.SendInput(id, "echo hello");
            return Task.CompletedTask;
        }));
    }
    public void Deactivate() { }
}

SendInput 默认只粘贴，显式 submit: true 才回车。查看、复制和模块切换不应执行命令。

4. 构建、导入、分发

dotnet build -c Release

导入 bin/Release/net8.0，确认模块显示和命令可用。禁用再启用，检查配置恢复与订阅清理。分发包含清单、插件 DLL、额外依赖和资源的目录，用户解压后导入。不要带入本地 settings 或 SSH 记录。

04 / REFERENCE

API 与生命周期

接口用途
RegisterView延迟创建并缓存模块。WorkspaceTools 由用户选择独立窗口、底部或右侧位置；Settings 在市场的插件设置页显示。
RegisterCommand命令面板、终端菜单与可选快捷键。
ReadConfiguration / SaveConfiguration按插件 ID 保存本机 JSON 配置。
Subscribe / Schedule / Track事件、计时器与资源，停用自动清理。
Lifetime / ReportError取消异步工作、报告插件错误。异步按钮自行捕获异常。
Host.Sessions / Workspaces会话、工作区信息和激活/创建/移动/分屏操作。
Host.ReadFrame独立稳定屏幕快照；按需读取，避免逐字符刷新 UI。
RegisterLocalization / Text中英文与回退；语言切换更新已创建控件，保留用户内容原文。

宿主和 UI 操作都在 UI 线程。后台任务通过 Avalonia Dispatcher 回到 UI 线程；停用后不继续更新界面或导出文件。关闭工具窗口不是停用，缓存页会保留。

主题使用动态资源 UiInk、UiMuted、UiSurface、UiInset、UiBorder、UiAccent，避免固定颜色。

05 / TROUBLESHOOTING

常见问题

导入时找不到清单或加载失败

选择直接包含 plugin.json 的目录，核对 entry DLL、完整 entryType、hostApi: 1 和 .NET 8 目标。插件卡片显示具体错误；额外依赖 DLL 也需要随包提供。

插件已启用，但看不到工具

默认打开位置是「独立窗口」，不会自动增加底部图标或右侧标签。在已安装插件卡片的「打开位置」中选择「底部工具栏」或「右侧边栏」，对应入口立即出现；也可直接点击「打开」。若仍没有入口，检查设置中的显示模块、当前工作区和显示快捷入口。Settings 模块在市场的插件设置页。

命令看板一直没有标记

Shell 或运行中的程序可能没有发送宿主支持的集成标记。启用后新命令才会被观察，不会猜测或补录之前的命令。

修改代码后没有变化

重建插件后重新导入。宿主单实例，新编译不会替换正在运行的旧应用；正常退出旧实例再启动新版本。
