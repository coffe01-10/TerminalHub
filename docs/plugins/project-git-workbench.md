# 项目导航与 Git 工作台

2026-10-05 本地开发交付。两个插件使用更新后的 API 1 宿主，默认在独立工作区工具窗口展示。也可选择原有监控／SSH／日志／Deploy 底部工具栏的入口，或原有右侧面板中的标签，工具栏入口在右侧打开插件页面。

## 安装

新版主程序顶部打开「插件」进入市场，在项目导航和 Git 工作台卡片点击「安装」，再点击「打开」。安装资源随程序附带，支持离线安装。位置、启动方式和插件选项见[市场与设置说明](marketplace.md)。

开发时也可运行 `pwsh -File scripts/build-official-plugins.ps1`，在市场「导入插件」分别选择 `artifacts/official-plugins/ProjectNavigator` 和 `GitWorkbench`。需要本轮更新后的主程序；旧版 0.4.0 和此前的 0.4.1 未包含新增目录接口。

已有终端不会因为导入、禁用或重新启用而关闭。新编译的主程序不会替换正在运行的旧实例。

## 项目导航

路径框回车或点击「进入」，目录列表显示文件夹名称，悬停查看完整路径，双击进入下级。面包屑、上级、后退与前进用于浏览，前后历史按工作区隔离。「选择文件夹」使用系统目录选择器。「打开文件夹」交给系统文件管理器。

「收藏与最近」页填写名称和分组，点击「收藏当前目录」。选择已有收藏后可修改名称、分组，再点「更新所选收藏」；上移、下移改变顺序。名称、分组和路径均可搜索。JSON 导入按路径合并，导出只携带收藏的名称、路径和分组，不携带终端或 SSH 配置。

收藏和最近访问在本机所有工作区共享；浏览位置与项目选择按工作区区分。关闭工具窗口、停用或重新启用后收藏仍在，移除插件会清除其配置。

「跟随当前终端」默认开启。手动浏览目录不会发送终端输入；「终端切到此处」只向明确指定的活动本地会话发送命令，并等待 Shell 报告实际目录。已知运行中的命令、AI 会话、备用屏幕或没有可用 Shell 集成时，使用「在此新建终端」。不支持自动切换的 Shell 可点击「粘贴目录命令」，检查后手动回车。SSH 路径保持远端语义，插件中的文件夹操作针对本地目录。

## Git 工作台

安装系统 Git 并沿用已有用户身份、SSH 或凭据助手配置；插件不保存密码或 token。可手动选择目录，也可跟随项目导航和活动本地终端。关闭跟随后，固定目录按工作区保存。

- 改动页区分未跟踪、未暂存、已暂存、冲突文件。同一文件同时存在两种改动时显示两项，分别查看对应差异。
- 暂存及取消暂存支持单文件和全部文件；提交只包含已暂存内容，提交区列出本次文件。
- 「分支」页包含新建／切换分支、远端与目标分支、Fetch／Pull／Push。没有仓库时可以在所选本地目录初始化。
- 「提交并推送」若提交成功、推送失败，会保留提交并清空已使用的提交信息；修正远端或认证后直接点「推送」。
- 冲突文件列在改动页，可用默认应用打开；处理并暂存后，在终端继续 merge／rebase。
- 提交历史默认显示最近 20 条，数量可设置，选择条目查看提交内容。
- 操作输出默认保留最近 30 次命令、工作目录、输出和退出码，数量可设置。取消只结束插件启动的 Git／gh 进程；取消之后刷新查看已实际发生的变化。

状态使用 [Git 官方的 porcelain v1 NUL 格式](https://git-scm.com/docs/git-status)，避免中文、空格和重命名箭头被显示转义干扰。未跟踪文本预览限制为前 128K 字符，二进制文件显示提示。

## GitHub

需要系统 `gh`；「GitHub 登录」打开运行 `gh auth login` 的一次性终端，登录交互交由 CLI。关闭再启动应用不会重放登录命令。没有登录、缺少 CLI 或网络失败时显示原因，本地 Git 功能继续可用。

GitHub 页可打开仓库主页、当前分支 PR，加载 PR／Issue 列表，查看正文并打开对应网页。检查状态使用 [gh pr checks](https://cli.github.com/manual/gh_pr_checks)，保留通过、失败、等待等实际状态；CLI 的“检查失败／等待”退出码不会误报成无法读取列表。

创建 PR 草稿前先推送当前分支，填写标题、描述与目标分支。创建使用显式 head，不触发隐式推送或创建 fork。从 Issue 创建分支时先选择 Issue，再填写分支名称和基础分支，执行 GitHub 的关联分支操作并检出到本地。详见 [gh pr create](https://cli.github.com/manual/gh_pr_create) 和 [gh issue develop](https://cli.github.com/manual/gh_issue_develop)。

## 验证范围

专项回归使用临时目录，退出时清除 Git 的只读对象及目录：真实 Git 验证中文与特殊文件名、初始仓库取消暂存、分阶段差异、重命名、工作树、游离 HEAD、本地 bare 远端的推送／获取／拉取、推送拒绝和冲突。实际 DLL 导入的 Avalonia Headless 回归覆盖收藏、排序、搜索、导入导出、工作区目录及后退历史隔离、跟随与远程隔离、提交和失败后重试。专项 14 项、含旧插件兼容的回归 21 项均通过；历史隔离修复后重跑 UI 7 项通过。

Windows 真实 ConPTY 验证含中文、空格、中括号及单引号目录切换，并在测试终端完成提交、向本地 bare 远端推送。最小工具窗口的英文界面、深色与 Paper 主题通过 Headless 检查及绘制检查。

同日市场与停靠版本先通过 61 项相关回归；按用户截图纠正为原工具栏与右侧面板后，63 项相关回归及最终 8 项市场设置复测通过，详情见[市场验证记录](marketplace.md#验证结果)。

GitHub 响应与命令参数采用回放验证，没有向用户 GitHub 仓库创建 PR／Issue 分支或推送测试提交。系统文件选择器／文件管理器的人工点击、GitHub 线上登录和写入、Linux 实机未执行。以上是验证边界，不影响本轮功能交付，也不记为永久阻塞项。
