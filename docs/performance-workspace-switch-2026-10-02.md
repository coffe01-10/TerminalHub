# 工作区切换性能（2026-10-02）

针对工作区标签切换的停顿，先测量当前实现，再在相同机器和负载下复测。应用进程与用户正在使用的窗口相互独立，没有结束用户已有终端，也没有读取个人会话配置。

## 改动与原因

- 原先清空当前会话后逐个加入目标会话，每一步都会刷新日志会话选项、重建缩略图列表并排队定位。改成一次发布完整会话列表、一次发布完整缩略图列表。每轮 40 次切换的会话列表通知由 440 次降到 40 次，缩略图列表通知由 800 次降到 40 次。
- 合并同一布局周期的缩略图滚动定位，去掉会话集合和缩略图集合对布局的重复触发。工作区已同步活动会话时，跳过随后排队的重复同步。
- 以会话对象为键复用缩略图控件，减少模板、绑定和字体布局的重复创建。缓存使用弱键，关闭会话后可以回收。分组或置顶重排时，尚在旧位置的控件不能同时放到新位置，因此该情况创建新视图；对应会话重启与分组回归曾抓到父级冲突。
- 点击工作区直接呈现目标终端，取消这一路径上的整块终端缩放与缩略图居中动画。同一工作区内的会话切换动画、固定侧栏的最小滚动、自动收起侧栏的滚轮居中逻辑继续保留。

## 测量方法

使用生产 Avalonia `MainWindow` 与真实 Windows ConPTY，Release 构建，窗口 1440×900、125% 缩放。环境为 Windows 10.0.26200、16 个逻辑处理器、.NET 8.0.31。

两个工作区各有 10 个 PowerShell 会话，每个会话连续打印带 ANSI 颜色的合成构建输出，每行后睡眠 50 ms。启动后预热 2.5 秒，再分别打开两个工作区各预热 500 ms。固定侧栏与自动收起且未呼出的侧栏各切换 40 次，每次完成布局后间隔 120 ms。

“命令耗时”包括同步 ViewModel 更新与绑定；“命令加布局”还包括 Loaded 优先级的排队工作和窗口布局。另用 Render 优先级的 16 ms 定时器记录 UI 调度间隔，反映 UI 线程停顿，**不是 GPU 帧率**。每个版本各完整采样一次，短期负载和调度会带来波动。

## 前后结果

单位为毫秒。

| 场景 | 指标 | 优化前 | 优化后 |
| --- | --- | ---: | ---: |
| 固定侧栏 | 命令平均耗时 | 544.65 | 66.49 |
| 固定侧栏 | 命令加布局平均耗时 | 601.81 | 128.81 |
| 固定侧栏 | 命令加布局 P95 | 696.87 | 162.21 |
| 固定侧栏 | UI 调度最长间隔 | 668.54 | 113.36 |
| 自动收起且未呼出 | 命令平均耗时 | 442.17 | 50.29 |
| 自动收起且未呼出 | 命令加布局平均耗时 | 446.96 | 55.27 |
| 自动收起且未呼出 | 命令加布局 P95 | 477.50 | 65.60 |
| 自动收起且未呼出 | UI 调度最长间隔 | 502.55 | 79.33 |

固定侧栏的切换加布局平均耗时减少约 79%，自动收起时减少约 88%。两轮结束时均有 20 个 PTY 仍在运行，切换没有重启会话。

高负载下仍有绘制和布局成本；这些结果不表示已经达到稳定 60 帧。原始报告还包含累计分配和应用 CPU 时间，但优化前后总采样时长不同，持续输出量也会不同，不能把累计值差异全部归因于单次切换优化。未测真实 AI CLI 的特定 TUI、系统输入法候选窗、多显示器或 Linux 桌面。

## 复测

Debug 与 Release 编译成功。工作区批量更新与缩略图复用、连续快速切换、分屏恢复与输入隔离、后台搜索定位、分组/置顶/重启、主题布局和侧栏呼出相关 61 项 Headless 回归通过。编译和上述测试不表示已更新安装包或正在运行的旧实例。

```powershell
dotnet run --project tools/TerminalHub.DesktopMeasurements -c Release -- artifacts/performance/workspace-switch-current.json --workspace-switch
```

工具只打开自己的测量窗口与 20 个合成负载 Shell，结束后关闭它们并删除自己的临时设置目录。报告保存到指定路径；不设性能通过阈值。此次原始报告分别为 `artifacts/performance/workspace-switch-before-2026-10-02.json` 与 `artifacts/performance/workspace-switch-after-2026-10-02.json`。
