# 审查剩余问题修复与测量

日期：2026-09-30。基于用户已有未提交修复继续处理，未回滚已有改动，未提交、推送或更新运行中的安装版。

## 修复结果

用户已有改动覆盖了非法 Unicode scalar、末列宽字、读循环异常隔离、Linux read 的 EINTR、设置加载失败保护、模板保存时序、分屏关闭、主要 VT 协议、选择、AltGr、Shell/SSH 参数及文件链接。本轮先运行这些修复相关回归，182 项通过，再补齐以下遗漏。

| 剩余问题 | 本轮处理 |
| --- | --- |
| 从滚动区下方 CUU 或上方 CUD，仍可能穿过另一侧边距 | 按移动方向和原始位置约束目标；从区外进入也停在另一侧边距。 |
| 冒号形式的 SGR 58 下划线颜色吞掉后续分号属性 | 整组子参数独立消费；即使暂不绘制下划线颜色，后续 blink/bold 仍有效。 |
| DECSTR 意外移动光标，RIS 留下历史与保存光标 | DECSTR 保留当前位置与内容、重置当前屏保存状态；RIS 清除历史与两套保存光标。 |
| Linux 子进程首次调用 `_exit` 的 P/Invoke stub | 父进程预解析 `_exit` 地址，子进程直接调用；预热使用空路径，避免修改父进程目录或意外执行真实 `/x`。 |
| 英文复数 warnings 支持后误把 `0 warnings` 归为警告 | 零计数和 `no warnings` 保持 info，`10 warnings` 保持 warn。 |
| 日志写入失败后状态仍声称写入、关闭 writer 也可能抛错 | 失败时关闭 sink，界面取消写入并显示错误；关闭失败不再中断退出，打开失败不留下已启用状态。 |
| 旧日志不断增长 | 按用户选择，在打开、轮转、关闭时保留最新 32 个日志文件；按最后写入时间排序，只匹配程序生成的时间戳文件名。活动文件及导出文件不删除，活动文件关闭后再清理。 |
| 空闲刷新与绘制分配 | 空闲 tick 跳过缓冲锁与重复 IME 查询；实际 IME 查询仍使用当前稳定帧。颜色画刷复用，上限 128 种。 |
| 滚动时保存过多完整帧 | 每个缓冲最多缓存 4 个帧，保留实时 offset 0 的复用，其他历史偏移淘汰。已交给调用方的稳定帧不受淘汰影响。 |
| 日志面板逐行重扫整个缓冲 | 新增、淘汰、容量调整和清除时增量维护级别统计，过滤不改变全缓冲计数。 |
| 空闲缩略图重复重建 | 内容版本不变时复用预览列表；新输出或 resize 后刷新，状态/目录仍按原机制更新。 |

滚动边距、DECSTR 和 RIS 的处理对照了 [Microsoft Terminal 的适配实现](https://github.com/microsoft/terminal/blob/main/src/terminal/adapter/adaptDispatch.cpp)。活动日志保护使用独占打开与 DeleteOnClose；Unix 本地文件的对应锁行为参考 [.NET 8 的 SafeFileHandle 实现](https://github.com/dotnet/runtime/blob/v8.0.0/src/libraries/System.Private.CoreLib/src/Microsoft/Win32/SafeHandles/SafeFileHandle.Unix.cs)。Linux 实机尚未验证。

32 × 16 MiB 约为 512 MiB。轮转发生在完整行写入之后，仍在写入或暂时无法删除的旧文件会保留，所以这不是目录的严格字节上限。清理没有在用户现有日志目录上手工执行，本轮使用隔离临时目录验证；应用使用新代码启用日志后执行上述策略。

## 同机测量

Windows、.NET SDK 8.0.425、Debug、Avalonia Headless/Skia，同一进程配置和负载，修复前后各测一次。6 个终端，焦点视图 131×29 格，其余 120×30 格；只有一个视图显示并获得焦点，绘制探针对 6 个视图逐一直接调用 Render。测量耗时及当前线程累计分配，不代表完整 GUI 的 CPU、GC 停顿或真实 CLI 吞吐量。

| 负载 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 空闲 tick：20,000 次 × 6 视图 | 91.08 ms / 40 B | 10.61 ms / 40 B |
| 静止内容 Render：100 次 × 6 视图 | 2,323.78 ms / 405,359,488 B | 1,552.63 ms / 306,131,360 B |
| 空闲会话卡片 Refresh：1,000 次 × 6 | 345.14 ms / 74,218,600 B | 0.63 ms / 864,040 B |
| 每轮新输出并绘制：100 次 × 6 | 1,647.45 ms / 417,571,296 B | 1,709.81 ms / 396,625,896 B |
| 1,000 行历史，每 20 行取帧 × 6 | 21.76 ms / 42,779,376 B | 19.11 ms / 42,751,888 B |
| 上述浏览结束，缓存完整格数组 | 294 帧 / 42,726,040 B | 24 帧 / 3,487,840 B |
| 5,000 行容量，追加 20,000 行日志 | 1,560.40 ms / 20,240,128 B | 56.13 ms / 19,440,040 B |

绘制负载包含 ANSI 颜色、中文及隐藏光标；连续输出每轮定位到第 3 行并改写文本。日志负载轮流追加 info/warn/error，模拟 Output 面板保留 500 行的逐行新增和淘汰；两次最终深缓冲统计均为 5,000 / 1,667 / 1,667 / 1,666。

空闲、静止绘制、日志统计和缓存保留有改善。连续输出绘制的单次耗时反而高约 3.8%，不能宣称吞吐量提高；该负载的分配下降约 5%。历史浏览的累计分配几乎不变，本轮减少的是长期保留的帧，未改变稳定快照必须复制格数组的设计。测量用临时探针已清除，不添加性能阈值门禁。
