# 多会话终端绘制测量（2026-10-01）

本轮对同机的 1／5／10 个会话做了空闲、一个会话输出、全部会话输出的比较。主要开销在文字绘制，保留已有稳定帧实现，新增终端行绘制复用；滚动时相同内容可以移到新行继续绘制。主题、字号和会话变化会更新绘制内容。快速切换先直接绘制首帧，第二帧再建立行缓存。

## 方法与边界

- Windows 10.0.26200，16 个逻辑处理器，.NET 8，Release 构建。
- Avalonia Headless 使用实际 Skia 文字排版和绘制，走实际 VT 解析、稳定帧、主视图及 StagePreview。每个模拟会话为 100×28 格，主视图 900×500，缩略图 240×135。
- 每项先预热 30 轮，再测 3 次，每次 300 轮。主视图输出每轮绘制，缩略图每三轮绘制，空闲主视图每 32 轮绘制。每个输出会话每轮收到一行带 ANSI 颜色的 ASCII 构建日志。主视图和缩略图共享同一模拟器。
- 这些轮次按 60／20 Hz 的相对频率模拟，但**不按真实时间等待**。处理耗时是完成固定工作量的时间；CPU 数据是测试进程消耗的 CPU 毫秒，不是桌面 CPU 占用率。没有运行真实 PTY 输出负载、系统监控面板或桌面合成器。
- 表中各指标取三次测量的中位数。切换数据来自随后 50 次切换及首帧绘制的 P95，不含应用现有切换动画。
- 原始数据保存在 `artifacts/performance/before.json`、`after.json`，汇总在 `comparison.json`。最终复测没有与其他构建或测试同时运行。

10 会话全部输出的固定负载处理耗时下降约 62%，累计托管分配下降约 9%。优化前此项绘制耗时中位数为 2415.4 ms，占处理时间约 96%；优化后为 860.0 ms。解析和稳定帧没有为此重构。

1 会话的“单个输出”和“全部输出”实际上是相同负载，但前者位于测试较早阶段，结果明显不同，说明字体／运行时预热及 GC 对短测量影响较大。保留所有数据，不据此宣称单会话 CPU 改善。空闲 CPU 的 0.0 ms 也只表示测量精度内未增加，不能解释为实际零占用。

行缓存有内存代价：10 会话全部输出阶段的测试进程工作集，中位数约从 131 MiB 增至 153 MiB。它包括整个测试进程此前各负载留下的对象与 GC 状态，并不是单独测出的应用内存增量。每个视图最多保留两屏行绘制，不缓存整段历史；脱离视图树后释放这些行绘制。本轮优先减少绘制时间，没有声称内存占用也下降。
