# 真实桌面与 ConPTY 测量（2026-10-02）

本轮补齐真实 Avalonia 主窗口和真实 Windows ConPTY 的负载测量。保留现有绘制缓存，没有从这组数据宣称优化降幅。原始报告在 `artifacts/performance/desktop-2026-10-02.json`，测量工具为 `tools/TerminalHub.DesktopMeasurements`。

## 方法

- Windows 10.0.26200，16 个逻辑处理器，.NET 8.0.31，Release 构建。
- 使用生产 `MainWindow`、实际桌面渲染和真实 `powershell.exe` ConPTY 子进程；非 Headless。主窗口 1440×900，一个显示器，125% 缩放。每次采样中窗口可见且活动。
- 1／5／10 会话各测空闲、一个输出、全部输出。每项预热 2.5 秒，采样约 6 秒；产生输出的 Shell 每行之后睡眠 50ms，名义目标为每秒 20 行，实际速率受调度影响。日志有 ANSI 颜色和 ASCII 构建内容。
- CPU 取应用进程 CPU 时间增量除以实际采样时间及 16 个逻辑处理器，是占整机的比例；不含 Shell 子进程及桌面合成器的 CPU。累计分配与工作集同样只属于应用进程。
- 每项独立新建主窗口与会话，但九项在同一进程顺序执行；工作集含此前缓存与 GC 状态。每项只测一次，不能作为稳定的前后性能比较。未自动操作系统输入法候选窗或多显示器。
- 工具的会话配置来自独立临时设置，负载为合成输出，不保存或输出个人配置，不结束用户已有终端；临时设置在该项 / 整轮结束后删除。报告只记录环境与测量数值。

10 会话全部输出约占整机 CPU 的 5.51%，折合单个逻辑处理器约 88.13%。输出增加时 CPU 和分配增加，现有缓存并未消除绘制成本。第一项空闲高于后续空闲，说明冷启动、字体或后台运行时活动仍影响短采样；不据此解释为会话越多越省 CPU。下一轮如需优化，应在相同负载下重复测量再比较具体改动。

## 重跑

```powershell
dotnet run --project tools/TerminalHub.DesktopMeasurements -c Release -- artifacts/performance/desktop-current.json
```

这是手动测量入口，会依次打开并关闭测试专用窗口和 PTY，约需两分钟。没有性能通过阈值，不加入日常测试门禁。可在 Linux 有图形桌面时运行同一工具，使用真实 Bash PTY；本轮未执行该平台。
